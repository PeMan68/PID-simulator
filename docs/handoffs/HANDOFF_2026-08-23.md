## 2. Produktvision

PID Simulator är en ren webbapp för undervisning och självstudier inom reglerteknik.

Appen ska främst stödja:
- lärarledda demonstrationer
- fler och snabbare experiment än fysiska laborationer medger
- självstudier genom lärstigar
- fördjupning inom reglerteknik
- träning i PID-tuning
- reglertekniska fenomen som är svåra att visa i fysisk labb

Simulatorn ska **inte** täcka hela kursens innehåll om mätdon och styrdon. Fokus är
regulatorn och reglerloopen:

```
process → mätdon → regulator → styrdon → process
```

Lärstigarna ska följa kursens veckoprogression och vara indelade i lämpliga
undervisningsportioner.

På längre sikt ska **spelifiering** införas (poäng, nivåer, progression, belöning för
övningar och tester) — men detta ska vänta tills den pedagogiska grunden är stabil. Det
nuvarande Test-läget med poängräkning är föregångaren till detta — tekniskt klart men
avsiktligt inte publicerat i v1.3.0 (se avsnitt 7).

## 3. Gitflow och livscykel

```
feature/<uppdrags-id>-<kort-namn>  →  develop
release/<version>                  →  main  →  tillbaka till develop
hotfix/<version>-<kort-namn>       →  main  →  tillbaka till develop
```

Regler:
- Ett uppdrag per feature branch.
- Feature branches mergeas aldrig direkt till `main`.
- Direkta commits till `main` ska inte göras.
- `main` ska innehålla stabil undervisningsversion.
- `develop` ska innehålla fortsatt utveckling.
- **Officiell GitHub Pages-URL publicerar nu uteslutande från `main`** (sedan
  RELEASE-v1.3.0 — `deploy-pid-simulator.yml` triggar bara på push till `main`, bygger med
  `node tests/build-preview.mjs prod` och publicerar `dist/prod/`).
- Release till `main` sker endast efter PO/PM-beslut.
- **Ingen cherry-pick eller selektiv release används.** En release tar med hela `develop`.

En funktion går genom fyra statusnivåer — se `docs/development/ENVIRONMENTS.md` (avsnitt
"Livscykel") för fullständig beskrivning:

1. **Under utveckling** — `feature/<id>-<namn>` → `develop`.
2. **Tekniskt klar** — mergad till `develop`, syns i DEV, avstängd/dold i PROD.
3. **Produktionsgodkänd** — PO godkänner; en separat liten branch (t.ex.
   `feature/PROD-enable-<id>`) lägger till den i `catalog.prod.json`/`env.prod.js`.
4. **Publicerad** — hela `develop` (inklusive godkännandet) går via `release/<version>` till
   `main`, som GitHub Pages publicerar från.

> **Merge till `develop` betyder tekniskt klar. Aktivering i PROD betyder
> produktionsgodkänd. Publicering från `main` betyder releasad.**

## 10. Kända tekniska förhållanden

**A. Två simuleringskärnor** — oförändrat. `apps/app/sim-core.js` delas med
`tests/simulation/`. `packages/sim-core` hör till den nedlagda Python-arkitekturen
(BESLUT-002) och ska inte blandas in utan separat arkitekturbeslut.

**B. Statusraden** — oförändrat sedan PED-003E. En decimal. `e`/visat `PV` kan avse
närliggande men olika beräkningsögonblick under transienter (mät → beräkna → agera-
ordning); noll vid sann steady-state. Ska inte ändras utan nytt uppdrag.

**C. PB (Proportionalband)** — oförändrat. `PB = 100/Kp`, PB=0 ej tekniskt nåbart.

**D. PID/D-termen** — oförändrat. `derivative = (PV − föregående PV) / dt`, undviker
derivatakick vid SP-ändring. Ofiltrerad.

**E. Innehåll** — oförändrat sedan PROD-001A: kosmetisk id-mismatch i
`processbegransningar.v1`, tre föräldralösa lärstigsfiler, fem DEV-scenarier utan
konsument-lärstig (varav två uttryckligen experimentella). Inget blockerar drift.

**F. Release-infrastruktur (nytt sedan RELEASE-v1.3.0)**
- `.github/workflows/ci.yml` — validering/byggning på push till
  `develop`/`feature/**`/`release/**` och PR mot `develop`/`main`. Publicerar aldrig Pages.
- `.github/workflows/deploy-pid-simulator.yml` — triggar **endast** på push till `main`.
  Bygger med `node tests/build-preview.mjs prod`, publicerar `dist/prod/`.
- Ingen `gh`-CLI eller autentiserad GitHub-åtkomst finns på den maskin RELEASE-v1.3.0
  kördes från. GitHub Release-posten "PID Simulator v1.3.0" skapades **inte** automatiskt —
  om den fortfarande saknas kan PO/PM skapa den manuellt via GitHub-webbgränssnittet
  (Releases → Draft a new release → välj taggen `v1.3.0` → fyll i titel "PID Simulator
  v1.3.0" → använd texten från `CHANGELOG.md` → Publish release, inte draft/pre-release).
  Branschskydd på `main` kunde av samma skäl inte läsas eller sättas — rulesets-listan var
  tom vid kontrolltillfället, klassisk branch protection-status okänd.
